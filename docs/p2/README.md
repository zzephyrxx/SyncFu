# P2：真实界面与手动同步闭环

## 当前状态

P2 源码已接入正式桌面入口。新版不再靠修改示例数组模拟同步；配对、目录授权、策略协商、检查、冲突比较/决策、风险预览、执行、核对和撤销都调用真实 Tauri 命令与 Rust 内核。

**尚未进行 Windows/macOS 实体双机验收，也未发布新安装包。** 本轮执行的是本机编译、临时目录的真实回环同步测试和开发专用 UI adapter 联调。浏览器截图明确带有 fixture 标识，不能作为实体设备结果。

- `/`：在桌面 WebView 中运行真实界面；普通浏览器仅显示“请使用桌面版”，不会伪造设备或统计。
- `/?prototype`：P0 第二版隔离演示，继续保留。
- `/?preview`：旧版只读示例预览，供回归。
- `/?desktop-test`：仅 Vite 开发模式的正式组件联调入口；使用内存 transport，顶部明确标识。已检查正式构建中不包含测试 transport、测试设备名或 `__SYNCFU_TEST__`。

## 已完成的闭环

1. **连接与目录**：真实动态码/对端确认、附近设备/手动地址、双方各自目录授权、新建关联。新 UI 的滚轮只展示后端签发的码，有效期取后端时间，不由动画重新延长。
2. **策略**：显示/提议方向与信任关系、对端接受/拒绝、策略核对、本机暂停。首次分类仍需对端确认，接收者不能替所有者改变规则。
3. **检查与比较**：真实文件差异、文本/二进制/缺失版本比较；未知/超大内容只显示元信息。结构冲突明确要求人工整理。
4. **决策**：按稳定设备 ID 选择版本，删改冲突可采用删除；支持当前筛选范围的批量选择、稍后处理、忽略当前版本、永久路径排除。
5. **最终审阅**：后端补齐必要父目录及目录删除依赖，返回最终选择；界面显示真实操作数和目标，风险批准绑定当前计划，不暗中多写文件。
6. **执行与恢复**：复用 P1 授权、备份、校验、部分完成核对及受保护撤销。普通未决冲突不阻塞其他已选文件；撤销后的新编辑不允许用普通冲突选版绕过。
7. **统计与设置**：本机统计由已核验完成记录产生；关闭统计不影响撤销历史。真实备份天数、容量、位置、开机启动、网络/权限检查均接到原生命令。外观/语言偏好与原型隔离保存。

## 冲突授权不是启用复选框

- `ConflictDescriptor` 绑定路径、稳定设备 ID → 内容状态、策略摘要及指纹。
- `resolve_plan` 接收的是路径和 `use/later/ignore_version`，不接受前端自造 before/after。
- 解析前重新核对两端内容和基线；成功后返回新 Plan ID/digest，并使旧预览失效。
- 使用某一端版本需当前策略管理权，且不能违背单向方向；shared 接收者伪造决策列表也不能放宽入站写入校验。
- 工作授权包含冲突决策和显式格式版本。普通双向写入仍要求目标未偏离基线；只有匹配的、经授权的冲突决策可替代这项条件。
- 覆盖、删除、目录依赖和异常清空继续进入既有风险及备份链，没有绕过路径。

### 文件预览边界

每端文本读取最多 **256 KiB**，只在授权根下读取普通文件，校验读取内容指纹。对端返回的 device ID、Entry、正文指纹再次校验，不能用另一段文本误导批准。

UTF-8 且不含 NUL 才作为文本；二进制、目录、缺失或超限分别返回明确原因。内容在 React 中作为文本呈现，不执行 HTML/脚本，不调用外部打开器。行差异使用最多 500×500 的有界 LCS，超出 500 行明确提示截断，不宣称显示了全文。

### 三种“不处理”

| 操作 | 作用域 | 持久化及后续 |
|---|---|---|
| 稍后处理 | 本机审阅 | 保留待决定项，不推进共同基线 |
| 忽略当前版本 | 本机审阅 | 绑定双端内容/策略指纹；任一端内容或策略改变后重新出现 |
| 永久排除路径 | 任务策略 | 复用双方策略提议/确认，影响同步和镜像清理；可从规则编辑中取消 |

本机审阅偏好不代表替另一位任务管理者作决定，界面有明确说明。批量审阅记录写入是事务性的，重启后保留，失败不会只写一半。

## 新命令与契约

延续 Rust Serde DTO → ts-rs 生成类型，权威文件为 `core/src/conflicts.rs`、`policy.rs`、`risk.rs`、`usage.rs`。生成入口不变，新增真实序列化夹具供前端验证。

| 命令 | 请求（Tauri camelCase） | 返回 |
|---|---|---|
| `resolve_plan` | plan, digest, decisions | 新 Plan |
| `preview_conflict` | plan, digest, path | ConflictPreview |
| `review_notes` | task | ReviewNote[] |
| `clear_review_note` | task, path | void；相关缓存计划失效 |
| `usage_report` | 无 | UsageReport |
| `set_usage_enabled` | enabled | void |
| `clear_usage` | 无 | void；不删除历史/任务/文件 |

`preview_execution` 现在返回后端展开后的 `selected`。正式界面必须据此确认；不依据原始前端选择数猜最终影响。

`Snapshot.protocol` 与生成的 `wireProtocol` 必须一致；旧内核搭配新页面会显示版本错误，而不是猜测缺失字段。

## 统计口径

- 只统计本版本实际记录的成功非空同步，旧历史不猜测补齐。
- 每批计一次；删除只计处理文件，不把被删内容大小当传输量；撤销/失败/取消不增加同步次数。
- `UsageRecord.bytes` 用十进制字符串保留精度，图表仅作单位化近似展示。
- 每端各自记本机参与的批次，不将两个设备统计相加当成独立传输量。
- 关闭统计期间不新增记录，重新开启不回填；清空统计与撤销历史分离。对端发起的完成批次也会触发本机总览刷新。

## 协议与迁移

- 对等帧协议 **3**，状态 schema **3**。两端必须同时更新，不能混用旧 0.1.0 测试包或 P1 协议 2。
- schema 2 升级前用 SQLite 一致性快照保存完整旧库；旧任务/历史/策略保留。
- P1 工作授权没有 P2 格式版本，视作 legacy，只可核对/恢复已移动的原件，不可重启后继续写入。
- 迁移测试仅使用临时数据库。未打开用户实际应用状态库，未自动回退实际文件。
- 源码快照：`artifacts/SyncFu-before-P2-verified-xtoWDN`。有新写入后不能只恢复旧数据库来回滚文件。
